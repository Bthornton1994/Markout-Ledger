# Markout Ledger

A research replay engine and append-only decision ledger for studying one question:

> Can a **slower controller** improve a **fast trading policy** by reviewing recent decisions, fills, costs and risk, then issuing bounded instructions for the next window?

This repository is **Milestone 1: a trustworthy, runnable replay and decision ledger**. It contains no live trading, no wallet, no exchange connectivity, no model calls and no RL training. Everything runs offline against replayed observations.

> **All fixtures shipped here are SYNTHETIC.** They are generated by a seeded simulator so the engine can be exercised deterministically. Every number this project prints is *synthetic research output* from a *paper execution model*. Nothing here is evidence of profitability. See [docs/DATA_REQUIREMENTS.md](docs/DATA_REQUIREMENTS.md).

[Jev Trader](https://github.com/jarrodwatts/jev-trader) is the inspiration for the fast/slow split. It is not a validated strategy and **no code from it is reused here**; this is an original implementation.

## Two clocks

| Clock | Cadence | Sees | Produces |
|---|---|---|---|
| Fast policy | every 300 ms (simulated) | observations with `obsTime <= now`, the active instruction, own inventory and resting orders | a desired quote state (bid/ask/hold/pull) |
| Slow controller | after every 3 s window | the completed window's review: activity, fills, costs, risk, and only those fill outcomes whose measurement horizon has elapsed | a typed, bounded, versioned **steering instruction** for the *next* window |

An instruction that arrives after the deadline, fails, or violates the contract is discarded and the previously accepted instruction stays in force. The controller is never invoked on the fast path. Details: [docs/CONTROLLER.md](docs/CONTROLLER.md).

## Quick start

Requires Node.js >= 22.

```bash
npm install
npm run typecheck      # tsc --noEmit
npm test               # vitest, behavioural tests
npm run demo           # replays both scenarios, prints summaries, writes out/<scenario>/
```

The same three commands run in CI on every pull request (`.github/workflows/ci.yml`), which also uploads the demo's `out/` directory as a build artifact.

`npm run demo` replays two fixed, seeded fixtures (13 and 12 controller windows) and compares three runs on each:

| run | what it is |
|---|---|
| `no_trade` | never quotes; the zero baseline |
| `unsteered` | the market-making policy with steering disabled (version-0 defaults throughout) |
| `steered` | the same policy steered by the deterministic controller |

Outputs per scenario: `out/<scenario>/results.json` (all three summaries plus a comparison block) and `out/<scenario>/<run>.ledger.jsonl` (the full hash-chained decision ledger). Replay commands and output layout: [docs/REPLAY.md](docs/REPLAY.md).

To regenerate the committed fixtures from their seeds (byte-identical, verified by a test): `npm run fixtures`.

## Guarantees the tests establish

Each of these is a test in `tests/` that exercises the public interfaces rather than internals:

- future observations cannot change an earlier decision (ledger prefix identical when the future is rewritten or removed)
- fill outcomes are unavailable to the controller until their measurement horizon has elapsed
- a steering instruction affects only the next window, applies from the first tick at or after it is ready, and is discarded when late, failed or invalid
- replay is deterministic (byte-identical ledgers; committed fixtures regenerate from their seeds)
- a book touch alone never creates a fill; a print at our price fills only past the displayed queue; a fill never exceeds the print; own orders at one price form a single FIFO, so time priority holds and a late earlier print can never break per-order monotonicity
- fill eligibility is decided on venue time: a trade printed before an order was live cannot fill it even if observed afterwards; a trade printed while live but observed after the cancel took effect is a late fill
- prints observed out of venue order are matched in venue order within a bounded window (the audit's Case B awards 0.300, not 1.000); awards only ever grow, so decisions stay causal
- every booked quantity cites its actual source print and venue time, never beyond that print's size, and becomes known only when the print that establishes it is observed; a later-observed earlier print that re-splits booked quantity moves provenance and outcome horizons without touching accounting, and configuration refuses horizons shorter than the staleness window so an outcome is never measured before its provenance has settled
- a stale-discarded print that was eligible for a resting order is recorded as order-linked uncertainty, never awarded; zero order and cancel latency replay cleanly
- the cancel/fill race is resolved consistently on venue time (fill wins at equal timestamps) and every order reaches exactly one terminal state
- the ledger is chronological: a malformed or out-of-order event later in the stream is rejected when encountered and leaves no trace in the earlier ledger prefix
- net P&L reconciles exactly with inventory, cash, fees and modeled execution costs, rebuilt independently from ledger events
- duplicate, out-of-order, stale, crossed and malformed observations are rejected and never reach the policy
- the risk gate blocks trades at the position limit and trips a kill switch at the loss limit; steering demonstrably changes the next window

## Status and non-goals

Milestone 1 delivers the engine, ledger contract and CLI. Not included by design: a dashboard, live data adapters, an actual model-backed controller, RL, order routing, or any credential handling. The synthetic generator is a test harness, not a market model.

License: not yet chosen by the repository owner. The repository is public; `package.json` still says `UNLICENSED` (and `private: true`, which only prevents npm publication). Until the owner picks a licence, no licence is granted.
