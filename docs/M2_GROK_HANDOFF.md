# Milestone 2 build handoff: the smallest implementation PRs

This is the bounded build task for the implementer (Grok). It implements [M2_DATA_CONTRACT.md](M2_DATA_CONTRACT.md) for the feed selected provisionally in [M2_DATA_SOURCE_DECISION.md](M2_DATA_SOURCE_DECISION.md) (conditions C1 to C5), **Kraken spot `BTC/USD`** over the public WebSocket API v2 (`book` at depth 100 with its in-band snapshot and per-message CRC32 checksum, `trade`, `instrument`; adapter `kraken-spot-ws2`, contract §8), and nothing else. Section 6 is the paste-ready prompt.

**Gate.** Nothing in this document is started until an independent read-only QA has cleared the corrected venue contract at the commit named in the pull request's QA request, and the owner has said so. Section 0 comes before section 1: first the owner's P0 listing (only after decision conditions C2 and C3 are met), then PR-0 as its own PR unless the owner substitutes a pair from that listing.

## 0. Prerequisite PR-0: versioned fixed-point precision migration

Why: contract §5.5. The selected instrument's quantity increment is `0.00000001` (`qty_precision` 8; the documented example and the official CLI fixture [S, R], which the P0 listing checks live) and the engine's `QTY_SCALE` is `1e-6`; the normalizer refuses the instrument (R5) on the current engine because a quantity like `0.00000001` cannot be represented without rounding, and rounding is forbidden. Prices (`price_precision` 1, increment `0.1`) already fit.

**P0, before any code (owner only, no PR, and only after the owner has met conditions C2 and C3 of M2_DATA_SOURCE_DECISION.md §1, because it is automated access to the venue).** From the host confirmed under C3, operated by the person confirmed under C3, take one public instrument snapshot (`{"method":"subscribe","params":{"channel":"instrument","snapshot":true}}` on `wss://ws.kraken.com/v2`, or `GET https://api.kraken.com/0/public/AssetPairs`) and list every pair with `qty_precision <= 6` **and** `price_precision <= 6` (REST: `lot_decimals <= 6` and `pair_decimals <= 6`), with `status`. Record `BTC/USD`'s values. If the owner substitutes a listed pair that meets the evaluation objective (a liquid USD spot market), PR-0 is skipped and the symbol in this handoff and in contract §8 changes, and the capture-day fee re-read of decision condition C4 (and protocol §2) follows the substitute, searching the eligible-pairs list under its WebSocket and REST names; otherwise PR-0 proceeds. Reference data only; no market data is captured, the venue's payload is never committed, and what the owner posts on pull request #3 is the owner's own derived statement (pair names as the endpoint used gives them, precisions, increments, status, and the date; a C2 use (iv) output, posted only as far as its attested clearance covers it), together with the choice between PR-0 and a substitute.
