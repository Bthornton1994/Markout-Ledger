# Milestone 2 build handoff: the smallest implementation PR

This is the bounded build task for the implementer (Grok). It implements [M2_DATA_CONTRACT.md](M2_DATA_CONTRACT.md) for the feed selected in [M2_DATA_SOURCE_DECISION.md](M2_DATA_SOURCE_DECISION.md), **Bybit spot BTCUSDT** over the public WebSocket stream `orderbook.50.BTCUSDT` with its in-band snapshot (adapter `bybit-spot-v5`, contract §8), and nothing else. The `orderbook.full` fallback (§8.1) and the Binance alternate (§8.6) are not part of this PR. Section 5 is the paste-ready prompt.

## 1. Scope of the PR (in)

| # | deliverable | where |
|---|---|---|
| S1 | **Raw capture tool**, market data only: connects to the venue's public WebSocket, subscribes to `orderbook.50.BTCUSDT` and `publicTrade.BTCUSDT`, fetches the instrument specification verbatim, runs the clock probes, writes raw capture format v1 (contract §4) with `recvWallMs` (`Date.now()`) and `recvMonoNs` (`process.hrtime.bigint()`) per record taken at receipt before parsing, maintains the same local book as the normalizer through the shared adapter module and performs the live checks of contract §8.1 (the `u` rule, a crossed book, a malformed depth update), resubscribing on any of them, rotates files hourly with per-file SHA-256, writes the manifest with the clock-sync report. Uses the built-in `WebSocket` and `fetch` of Node 22.4 or later (set `engines.node` to `>=22.4`); no new runtime dependency. CLI: `normalize --raw <dir> --out <dir> --rights <json> [--depth 20] [--min-windows 10] [--window-ms 3000]`; outputs `<captureId>-seg<segmentIndex>.jsonl` and `<same>.normalize-report.json`. | `src/normalize/` |

## 2. Out of scope (do not add)

- Any order placement, account, wallet, API key, credential handling, or Jev integration.
- Any RL, RLVR, model-backed controller, or change to the controller contract.
- Any change to matching (`src/execution/paper.ts`), accounting (`src/portfolio/`), risk, the controller, or the ledger schema (`src/ledger/`). The optimistic queue variant named in M2_EVALUATION_PROTOCOL.md §2 is a later PR.
- The `orderbook.full` fallback stream, the Binance alternate adapter, and third-party recorded data (`third_party_receive`).
- A sensitivity-grid CLI: the grid is produced programmatically with `replay()` in a later PR.
- Committing any recorded data whose `rights` block is not `permitted` + `sample_permitted`.

## 3. Acceptance tests

All tests use the existing style (vitest, behaviour through public interfaces). Generated raw captures use the venue's real frame format. "Byte-identical" means the serialized files compare equal with `cmp`. "The clean capture" is the generator's default output: one snapshot, contiguous deltas, trades that print through the quoted level so the unsteered run fills, no anomalies.

| id | test | passes when |
|---|---|---|
| A1 | normalize determinism and integrity | the same raw files normalized twice yield byte-identical fixture files and normalize reports; changing one byte inside a raw file makes normalization refuse under R1b naming the file; a raw file whose `manifest_end` lists a different hash is refused |
| A2 | replay of the clean capture | the normalized fixture replays twice with byte-identical ledgers for all three run kinds and identical `results.json` (output paths aside); `observations.rejected == 0`, `observations.accepted == eventCount`, and the unsteered run has `fills.count > 0` |
| A3 | observation-time causality | (a) for every `policy_decision`, the book it cites has `obsTime <= simTime`; (b) for every `fill`, `observedAt >= sourceMarketTime` and `observedAt >=` the establishing print's `obsTime`; (c) two complete generated captures, the second identical to the first but ending earlier with its own `file_end`/`manifest_end`, both normalize, and the ledger prefix up to the shorter fixture's `endTime` (excluding `replay_started` and hashes) is identical |
| A4 | three-run comparison | `no_trade`, `unsteered`, `steered` replay the same recorded fixture (same content hash in all three `replay_started`), `no_trade` has zero fills, the comparison block is present, and the recorded disclaimer wording appears in `results.json` and every summary |
| A5 | ledger reconciliation | `Ledger.verify` passes and cash, inventory, fees, message costs and gross realized P&L rebuilt from `fill` and `tx_cost` entries equal the summary exactly, for all three runs |
| A6 | assumptions exposed | `results.json` shows per run `config.execution.orderLatencyMs`, `config.execution.cancelLatencyMs`, `config.execution.makerFeeBps`, `config.execution.placementCost`, `config.execution.cancelCost`, `config.maxStalenessMs`, `fillUncertainty`, `fills.uncertain`, `fills.lateAfterCancel`, `portfolio.feesPaid`, `portfolio.txCostsPaid`, and `fixture.header.provenance.capture.lagStatsMs`, `.clockSync`, `.venueClockOffsetMs`, `provenance.rights`; the console header prints the staleness limit, lag statistics, clock sync, offset and rights |
| A7 | gaps | a capture with a `u` jump yields a segment ending at the record before the jump (`endReason: gap_sequence`, `endRawRecord` exact), trades received before the jump-revealing record included and matched, no book event from stale state, and a second segment starting at the next snapshot (`resync_after_gap`); a `u == 1` delta and a backward `u` delta each end the segment the same way; a `ws_close` without a following snapshot ends the segment with `gap_disconnect`; each cut appears in `cuts` with reason, `fileIndex` and `record`; capture side, the runner fed a `u` jump and then a crossed delta by a fake WebSocket server writes a `note`, an `unsubscribe` and a `subscribe` record after each, with the revealing frames recorded verbatim |
| A8 | reordering and clocks | (a) a trade received after a later-venue-time delta stays in arrival order with non-decreasing `obsTime`, and the engine's fill totals equal those of the in-order permutation (per the M1 Case B tests); (b) a backward `recvWallMs` step and a forward jump beyond `Δmono + 10 ms` each cut the segment at that record with the next segment starting there (`resync_after_clock_cut`) and the book carried over; (c) a fixture hand-edited to violate `obsTime` ordering is rejected by the engine as `out_of_order` with the earlier ledger prefix unchanged |
| A9 | malformed and duplicate source items | an undecodable frame, an off-tick price, an off-lot size, a non-positive trade size, a duplicate trade `i`, a duplicate depth `u`, a size-zero for an unknown level, and an off-book trade (`BT` or `RPI` true) are each counted under their named `dropped.*` key and not emitted; a malformed depth update cuts the segment (`malformed_depth`); a snapshot never followed by `u + 1` is refused as `reconstruction_failure`; a frame with three trades whose UUIDs decrease lexicographically emits all three with distinct `eventId`s and the engine accepts all three |
| A10 | rights gate | the normalizer refuses to write a fixture without a valid `--rights` file (R8); a repository test enumerates `fixtures/*.jsonl` and fails on any `synthetic: false` fixture whose `provenance.rights` is not `permitted` + `sample_permitted` with a terms URL and date |
| A11 | receive-clock rules | a raw file whose records lack `recvWallMs`/`recvMonoNs` is refused (R1); a segment with more than 0.1% negative lag is refused (R2); a capture whose clock probes imply an offset beyond 50 ms is refused (R2b); for every emitted event `obsTime` equals the `recvWallMs` of the raw record named by its `rawRef`, and every `eventId` in a segment is unique; a fixture whose header says `third_party_receive` is rejected by `validateHeader` |
| A12 | real session (manual, reported) | one first-party capture of at least 60 minutes on Bybit spot BTCUSDT from an NTP-disciplined host: normalize twice (A1), replay twice (A2), report raw file hashes, fixture content hash, segment start/end reasons, `sequenceJumps`, `lagStatsMs`, `venueClockOffsetMs`, `clockSync`, drop counts, rejection counts by reason, the three-run table, `fills.uncertain` and `queueConsumedWithoutFill`. The table is a single-cell mechanics check, labelled as such (M2_EVALUATION_PROTOCOL.md §4); data committed only if A10 allows |

## 4. Definition of done

- `npm run typecheck`, `npm test`, `npm run demo` pass; the two committed synthetic fixtures are byte-identical to before (the existing test "regenerates the committed fixtures byte-for-byte from their seeds" still passes).
- A1 to A11 are in CI; A12's evidence is in the PR description.
- The PR touches nothing under `src/execution`, `src/portfolio`, `src/risk`, `src/controller`, `src/ledger`.
- The PR is a draft and is not merged by the implementer.
