# Milestone 2 data-source decision

Date checked for every source below: **2026-09-22** (the first version of this document, dated 2026-09-18, selected Bybit; that selection is withdrawn, §1). How sources were checked is stated per item, because this evaluation was done from an environment whose egress policy blocks every venue website: official documentation and code that venues publish in public GitHub repositories was read at a pinned commit (**[R]**); everything else (documentation pages, terms, pricing, historical archives, geographic restrictions) is known only through search-tool excerpts of the official page (**[S]**), which are not authoritative and must be re-read on the live page by the owner before capture begins; third-party implementations are corroboration only (**[T]**); anything that could not be verified is **[U]**, and nothing marked [U] or [S] is treated as a right, a guarantee or a permission.

## 1. Decision

**Selected: Kraken spot `BTC/USD`, captured first party from the public WebSocket API v2 (`wss://ws.kraken.com/v2`): the `book` channel at depth 100 with its in-band snapshot and per-message CRC32 checksum, the `trade` channel, and the `instrument` channel.** Adapter mapping: M2_DATA_CONTRACT.md §8.

Why this one:

- The venue serves clients in the United States, where this project is operated; the official US quick-start page lists only New York and Maine as excluded states [S]. Bybit, the previous selection, excludes the United States on its official restricted-countries page (`bybit.com/en/help-center/article/Service-Restricted-Countries`), so its capture requirement was not executable; Binance has the same exclusion [S].
- Public market data needs no account or key: the official Go SDK subscribes to `book`, `trade` and `instrument` with no token and calls `/0/public/*` without authentication [R]; the venue's WebSocket FAQ and introduction say the same [S].
- The book can be reconstructed **fail closed**: every book message carries a CRC32 checksum of the top 10 levels per side after the message is applied; the algorithm is implemented in the venue's official Go SDK and pinned with the venue's documented worked example in its official Rust SDK tests [R]. No sequence number exists on book messages (none in any official type or fixture [R]; none located in documentation [S]), and none is assumed.
- Trades name the taker side (`side`), carry a per-book sequential `trade_id`, the taker order type and an RFC 3339 timestamp with microseconds [R types, S descriptions]; several trades may share one message and batching does not imply one taker order [S].
- The instrument channel publishes explicit `price_increment`, `qty_increment`, `price_precision` and `qty_precision` per pair [R types, S example], so the precision check of contract §5.5 is mechanical.
- Every message shape, the checksum, the reconnection behaviour and the keepalive cadence were read from the venue's official repositories at pinned commits [R] (§5), so the adapter can be implemented without access to the website; the remaining semantics are [S] and listed as owner reading (§4).

Conditions attached to the decision (each is blocking until met; none is a checklist nicety):

- **C1, precision.** `BTC/USD` has `qty_precision` 8 (`qty_increment` `1e-08`) [S example, R fixture]; the engine's `QTY_SCALE` is `1e-6`. The normalizer refuses the instrument on the current engine (contract §5.5, R5). Either the versioned precision migration lands first (M2_GROK_HANDOFF.md §0, PR-0) or the owner substitutes a Kraken pair with `qty_precision <= 6` and `price_precision <= 6` after the P0 listing; no such pair has been verified from here (§4). Nothing is rounded or truncated in any case.
- **C2, rights and terms, read by a person.** US clients contract with Payward Interactive, Inc. under the Global Terms of Service [S]. The search-visible Global Terms say Kraken owns all content on its services and platforms ("Our Content"), permit use "only for their own benefit" under a revocable permission, prohibit copying, modifying, distributing or otherwise commercially exploiting Our Content, route any other use to `legal@kraken.com`, and prohibit "web scraping, web harvesting, or data extraction methods" and "bots, robots, parsers, spiders, scripts, programs, routines, or any other forms of automation" against the platform, in a sentence the search tool truncated [S]. Whether the documented public API is carved out of that automation clause is **unknown**; the venue publishes SDKs and a CLI for exactly that use, and its official SDK disclaimer says API use "remains governed by the applicable Kraken terms of service and API terms" [R], but no separate API terms page was found [U]. Therefore: before any capture, the owner reads the Global Terms in full (URLs in §4); if the automation clause does not plainly exempt use of the documented public API, the owner obtains written permission from `legal@kraken.com` first. No clause about AI or machine-learning training was located, which is an unknown, not a permission [U]. Until the reading establishes more, the only admissible `rights` block for this venue is `redistribution: "unclear"` (or `"prohibited"`) with `publication: "hash_only"`; raw captures never enter Git; the repository carries hashes, provenance and schemas only (contract §6.3).
- **C3, jurisdiction.** The capture host and its operator are in a US state the venue serves (not New York or Maine; Washington is not in the exclusion list per the excerpt but must be confirmed [S]); no geographic workaround of any kind.
- **C4, fees.** The recorded scenario's `makerFeeBps` is read by a person from the fee page on the capture day and recorded with the run: the search-visible headline is 0.25% maker and 0.40% taker at the lowest tier with a tier-basis change on 2026-07-09 [S], while the venue's official CLI hard-codes 0.16% maker and 0.26% taker as a "Starter tier default" [R], which conflicts and looks stale. The sensitivity grid sweeps the fee in any case.
- **C5, owner pre-capture checklist.** §4 lists every [S] and [U] item with its URL; each is read on the live page and its date recorded before the first capture.

**Alternates.** None is specified on the same contract. Coinbase, Gemini, Bitstamp and Binance.US were evaluated (§3) and rejected for the reasons given there; Bybit and Binance are rejected on jurisdiction; Hyperliquid is rejected on data mechanics and jurisdiction; Kuru `MON-USDC` on Monad remains a deferred research target for the reasons recorded on 2026-09-18 (block timestamps at one-second granularity with 300 ms blocks, AMM liquidity outside the order events, contract migration); third-party recorded data (Tardis.dev) is not a replay basis this build accepts.

## 4. What could not be verified from this environment (owner reading before the first capture)

Every item is [S] or [U] above. Read on the live page, record the date, and keep the reading with the capture's `rights` block:
